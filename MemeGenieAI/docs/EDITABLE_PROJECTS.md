# Editable memes and local AI captions (development)

Launch **Meme Genie AI - Development Test**. Save your current editable project before restarting to load source changes. The frozen package has not been rebuilt; current live windows are not hot-reloaded.

## Main workflow

1. Choose Background.
2. Type a caption, or enter a short idea/tone and choose **AI: Suggest memes**. The local vision model sees a resized copy of the image and proposes editable captions, placement, font style and colors. Compare the two independently generated ideas in the preview selector, then Apply the selected idea or Cancel. Duplicate caption proposals are rejected. Applying replaces current captions; cancellation or errors leave them unchanged.
3. Font, size, position, color and alignment controls remain visible and editable. Add text creates another layer. The optional automatic-arrangement checkbox/button uses deterministic CPU rules, not a model. It is off by default and is turned off when applying AI suggestions or opening a project, so later manual edits are not rearranged.
4. Export Meme saves flattened PNG/JPEG. YouTube/Short exports resize the background before laying out text. File > Save Editable Project stores an editable `.mgproject` with its original embedded background and layer data. Open Editable Project restores it.

Every explicit image export includes the original visible credit: **Generated by Meme Genie, by @kaotickj: https://github.com/kaotickj**. This is mandatory, with no toggle. Base-image Save also adds credit without altering the editable background. The rendered meme is fitted above a separate credit strip, so bottom captions are not overwritten. Tiny images may gain canvas space to keep the complete credit readable. Project background storage is not a finished export.

## Local AI requirements and limits

Local Ollama at `127.0.0.1:11434` must already be running with an installed vision-capable model. The existing `gemma3:4b` was verified through a real CPU image-understanding test. A bounded Qwen3.5 9B CPU comparison worked but took about 125 seconds for one proposal and did not demonstrate better design quality than Gemma3 4B; the default was not changed. Gemma4 remains untested. No model is downloaded automatically. Requests leave GPU offload and thread selection to the existing backend, with a 4,096-token context, bounded output and timeout. No hardware or service settings are changed. The older CPU-only evaluations below describe historical tests, not a current restriction. A multi-idea response can take longer than a single suggestion. Images stay on the local machine; HTTP proxy routing and redirects are disabled. No cloud API is used.

Only validated structured data is accepted. Model output is never executed. A failed request does not silently substitute a heuristic or claim AI success. Model descriptions and design taste can be wrong; preview before applying. During an active CPU request the app waits for completion/timeout before closing safely. Generation of new background artwork remains experimental and is available under Tools, not the primary workflow.

Up to 20 editable layers are supported. Fonts are not embedded; unavailable fonts fall back. Extremely long text can still clip. Project writes are atomic; malformed/oversized projects are rejected before editor replacement. There is no undo/redo or automatic recovery yet. **Save your editable project before closing.**

Validation includes CPU tests for structured-output rejection, proposal Cancel/Apply, layer editing, source preservation, atomic project saves, mandatory credit, PNG/JPEG and sized exports. A real Qt GUI run on an isolated X display verified keyboard entry, image export and exact-pixel project save/restart/reopen without touching the user's live session.

## Image library

Clear Image Library hides the current folder's entries only in Meme Genie's view, with count and confirmation. It does not delete, move or hide files on disk, alter projects, or clear the current editor. Restore cleared library entries reverses it. New/changed image files appear normally.

## Composition review (2026-11-10)

AI requests now include measured texture and light/dark contrast for candidate caption areas on the selected crop. These are advisory: low texture does not establish that an area is free of faces or important objects. The vision model still chooses the composition. AI caption fitting limits each caption to a quarter of the canvas height and shrinks it further when another caption is below it. Manual text controls remain unchanged. The renderer now resolves requested installed font names even without an explicit font map, with a bold fallback for unavailable fonts.

A real Gemma3 4B CPU run on the prior session's blues-band image took about 71 seconds and returned distinct serif and monospace alternatives. Visual inspection exposed an oversized text column over the guitarist; the subsequent height limit corrected that column. The captions were still weak, and one placement still overlapped the performer's hat. This is incremental composition support, not verified subject-aware placement or consistently strong humor. All results still require preview and may need manual adjustment. No GPU, model download, editor restart, merge, or release was required.

## Subject-aware composition and caption writing (development, 2026-11-10)

Normal suggestions now request one caption layer per alternative. An independent writing pass uses the same selected local model, without copying its first drafts, to develop different joke premises. Wide crops have an 80-character writing budget; other crops use 90. Quoted/exact wording and explicitly requested multi-layer copy bypass rewriting. The full request has a shared five-minute budget and remains CPU-only. Model selection, models, persisted settings, and the live editor are unchanged.

The vision model reports protected heads and key objects. The compositor validates those boxes, supports the observed 0–1000 coordinate-grid variant, clips partly visible objects to the canvas, adds head clearance, and searches using actual rendered caption bounds. It preserves readable text size, reading order, and contrast. An unusable proposal is omitted; if none fit, the app reports the problem and leaves existing text untouched. Applied proposals retain their checked positions rather than being moved by the older generic fitter. Manual editing remains unrestricted, and the exact mandatory attribution is unchanged.

### What the real evaluations showed

- Gemma3 4B completed the two-pass band-image workflow in about 107 seconds and produced bold/serif alternatives. Its subject boxes were inaccurate and its jokes remained uneven. Do not treat those boxes as reliable face detection.
- Qwen3.5 9B identified the three main performers and guitar much more accurately in this example, but image analysis took several minutes. Its responses exposed two compatibility cases: mixed 0–1000/fractional coordinates and an object extending beyond the crop. Both are now handled and regression-tested. A subsequent complete all-Qwen widescreen run is documented below.
- Rendered replays combining recorded Qwen subject boxes with previously generated short Gemma captions produced a compact serif caption between heads and a bold lower-left caption. Those replays used explicit design profiles; they are component checks, not an end-to-end model-quality benchmark.
- Longer Qwen captions could not fit at the minimum readable size. This motivated the tighter wide-crop writing budget. Extra Gemma/Qwen 4B/8B rewriting experiments did not establish consistently good humor; they did not change the app's model selection.

Subject protection remains dependent on model localization and can miss faces or objects. Review the actual preview before Apply. Good geometry and passing tests do not establish good humor. Current source changes require a saved restart to appear; the frozen package and active window were not replaced.

## Complete Qwen widescreen evaluation (2026-11-10)

The corrected image analysis → caption rewrite → protected placement → actual PNG export workflow was exercised with Qwen3.5 9B on CPU, using the band image and a 1920×1080 crop. All requests specified zero GPU layers; Ollama reported zero GPU memory. The active editor and the GPU reserved for Speak As were untouched.

The first run hit the normal 300-second limit during image analysis. A second diagnostic allowed 600 seconds but finished in 288 seconds: 250.7 seconds for the image/design pass and 34.7 seconds for rewriting. It exported one surviving option, “One chord fixes what three sessions can't.” Preview and saved PNG matched exactly. Yellow monospace text occupies the lower left and leaves the main performers' faces clear; the original mandatory GitHub credit remains visible. The other caption, “My therapist charges more than this guy's hat.”, was rejected for lack of readable protected space. It was also a weak joke.

Assessment: a usable, mildly witty result, not evidence of consistently strong comedy. Only one alternative survived, the crowd was not protected as thoroughly as the performers, and latency varied enough to cause one timeout. Portrait composition and repeatability were not evaluated in this run.

The successful writing pass spent 10.5 seconds reloading the model (the first load took 47.5 seconds). The image pass now keeps the model resident briefly for the writing pass; that final pass still requests unloading. If writing never runs, the reservation expires after two minutes. This uses the documented per-request `keep_alive` option, not a persisted model setting: https://docs.ollama.com/api/chat . The five-minute app deadline is unchanged. A subsequent full CPU run measured the writing-pass load at roughly 1 millisecond, down from 10.5 seconds. Total elapsed time fell from 288 to 250 seconds, but initial load time and generated token counts also varied; the whole difference cannot be attributed to retention.


## CPU repeat requests and fitting review (2026-11-10)

Normal repeat suggestions reuse validated scene observations for the same image pixels, crop, brief, model and model digest. The process-local cache holds at most two entries for ten minutes and stores no image files. Every repeat still writes fresh captions. **Recheck image** discards matching observations and reruns vision when the picture was misunderstood. Exact/quoted wording and multi-layer output bypass this cache. No persistent model settings change.

Fresh Qwen CPU scene analysis took 222–231 seconds in these trials. A genuine cached repeat skipped the image request and completed in 40 seconds, although its output failed placement. Another repeat including a shortening retry took 68 seconds and also failed. These timings establish reduced inference work, not reliable successful-meme latency.

The decoder now has room to finish sentences instead of forcibly closing strings at the layout character limit. Overlong or obviously unfinished captions receive at most one shortening pass within the shared deadline; valid alternatives survive when another remains unsuitable. This catches some incomplete sentences, not every grammar or humor problem. The original writing prompt remains: experimental prompts did not demonstrate consistently better comedy.

Placement searches subject boundaries as well as the coarse grid. AI fitting shares the renderer's wrapping and measures descenders and shadows, fixing a false rejection of usable bottom space. Captions still must fit at the minimum readable size and avoid the reported protected regions.

The final continuation used recorded validated scene analysis, a new live CPU writing call, and actual widescreen PNG exports. It completed in 39.3 seconds; both saved images matched their previews exactly. Serif and monospace alternatives fit at the lower left without clipping, leave the three main faces clear, and retain the exact visible attribution. They occupy the same available region and overlap some drum/background detail. The captions were complete but weak: “My therapist said I'm angry but this blue note fixed it instantly.” and “I just jammed my head into the mic because talking to people costs money.” This was a cached-scene continuation, not a new live vision benchmark or evidence of improved wit.

Remaining limitations: first-use CPU latency is still several minutes; vision can incorrectly protect whole bodies and leave no usable space; humor is inconsistent; font variation does not guarantee meaningful composition variety. Final changes were reviewed on widescreen output; Shorts controls and export tests remain, but a new live portrait-model evaluation was not performed. Development source only: active editor, models, settings and frozen package were preserved; nothing was merged or published.


## Portrait and widescreen follow-up (2026-11-10)

A checkpoint archive of all modified and untracked development files was saved before this evaluation. The installed app and running editor were untouched.

Fresh Gemma3 4B CPU runs on the same band photograph completed the full vision → writing → placement → PNG workflow in **97.3 seconds for Shorts (1080×1920)** and **98.1 seconds for widescreen (1920×1080)**. Each produced two exports with exact preview/export pixel equality and the mandatory visible credit. The portrait crop isolates the drummer; it was analyzed independently from widescreen. Inspection found poor portrait columns and inaccurate subject boxes (including a drum box over the upper wall). Widescreen text was readable, but the captions remained generic. These successful exports are not evidence of good humor or accurate subject detection.

Two prompt experiments were rejected: a shorter first-person prompt yielded generic price comparisons, and a fresh portrait vision prompt excluding incidental scenery still returned inaccurate boxes and weak captions. Neither experimental prompt was installed.

The retained change is limited to AI placement readability: tall portrait crops require a minimum suggested size of 24 relative to a 512-pixel width (other crops retain 16), and the scorer favors compact blocks over columns longer than roughly three lines. A model's tiny proposal can be enlarged and repositioned; if it cannot fit readably outside the reported regions, it is rejected. Manual font size and positioning remain unrestricted.

Deterministic replays of six recorded model outputs (four portrait, two wide) verified the final placement change with actual exports. Portrait columns became wider three-line blocks; the tiny portrait proposal became a readable header. The two widescreen layouts were unchanged. All six exports matched their previews exactly. These are recorded scene/caption replays, not fresh model inference. The baseline portrait captions moved over the bass drum because the model failed to protect its actual location; the face remains clear. Better readability does not fix those subject boxes or weak jokes. The portrait credit remains visible but small at a phone-sized preview.

Validation: 91 tests passed, including a new portrait readability regression checking source-layer preservation and protected-region clearance at export resolution. No GPU workload, installed-app replacement, merge, or publication was performed. Evaluation artifacts and checkpoint manifests are in the task workspace under `meme-genie-review/portrait-checkpoint`.


## Exact copy, subject correction, and acceleration (2026-11-11)

The caption path no longer sends `num_gpu=0` or a fixed thread count. The existing model backend selects acceleration; no power, clock, thermal, driver, service, model, or installed-app settings were changed. The status message no longer claims that caption generation runs on CPU. During a live Qwen experiment, `/api/ps` reported `size_vram: 0` despite no GPU override in either request. This is the observed backend allocation, not a restriction imposed by the editor.

Explicit quoted exact-copy instructions now restore the user's text deterministically after model validation and before placement. A model that supplies a different caption cannot silently substitute it. For example, `Use these words exactly: "My solo has a copay."` retains that wording in every alternative. Intentional quoted top/bottom copy can produce separate layers even when the model omits one. Ambiguous literal-copy instructions are rejected before inference with a request for clearly quoted copy. Manual text editing remains unrestricted. Adversarial tests cover wrong model text in both single and multiple-proposal paths; four actual portrait/wide PNG exports preserved the requested words and matched their previews exactly.

The suggestion preview now offers **Keep an area clear**. Enable it and drag over a missed face or object on the selected crop. Up to four marked areas augment the model's regions; every alternative is repositioned locally without another inference call. **Undo area** removes the most recent correction. If readable placement is impossible, Apply is disabled for that alternative instead of accepting an overlap. Cancel preserves existing editor content. Protection marks belong to this suggestion review and are not embedded in the image or saved as constraints on later manual edits. The applied text positions remain editable and save normally in projects.

Real-image GUI review used recorded model outputs rather than pretending to run fresh vision. In portrait, protecting the actual lower drum kit moved a caption off the bass drum into the remaining upper-left space. That leaves a narrow text column because the original model incorrectly protected empty upper-wall space. In widescreen, protecting the guitar narrowed the caption to the left, leaving the marked instrument clear. Both corrected PNGs matched their previews exactly, and full-resolution text masks had zero overlap with the marked areas. The exact original attribution remained visible. The correction improves control over missed subjects; it does not repair the model's false-positive boxes or guarantee automatic localization.

Rejected experiments retained for review:

- A labeled 4×4 image-grid localization trial with Gemma took 44.9 seconds portrait and 51.7 seconds wide. It mislocated the drummer and confused reference labels with subjects. It was not installed.
- A different caption approach generated six candidates and used a second pass to select two. Gemma took 30.6/30.9 seconds and Qwen3.5 took 113.5/86.7 seconds for portrait/wide scene descriptions. Both selectors favored generic comparisons while calling them surprising jokes. Some candidates invented unsupported details or made cure claims. The candidate-selection pipeline was not installed; its favorable self-reviews are not treated as evidence of quality.

These experiments used existing models only and were sequential. The first grid trial used the previous CPU constraint; subsequent trials omitted GPU and thread overrides after the user's updated instruction. No model downloads or unrelated service changes occurred.

Validation: 106 tests pass, including real pointer-drag mapping in portrait and wide viewports, Apply/Cancel, no-space rejection, Undo, exact-copy preservation, and backend-option checks. Image-library data, manual controls, and original mandatory attribution were preserved. Caption humor and automatic subject localization remain unfinished work. Development branch only; no merge, publication, or installed-app replacement.

## Reviewable subject areas and compact portrait composition (2026-11-11)

The suggestion preview now has **Review subject areas**. The numbered boxes can be selected directly on the image or from a list. **Redraw area** replaces an inaccurate box; **Remove area** removes a false detection; **Undo area** reverses either action as well as added protection. Matching scene boxes are corrected across the available caption alternatives. The original model output and the manual editor are not changed unless Apply is accepted. Dashed outlines show the same clearance margin used by placement. A hand-redrawn head box keeps the standard margin rather than receiving an additional guessed chin extension.

Corrections are local and do not rerun a model or train detection. If every proposed caption is blocked, the preview still opens for area review and keeps Apply disabled until a valid placement is found. Portrait suggestions reject accidental columns longer than four wrapped lines (explicit line breaks remain intentional), retain the existing minimum readable font size, and never shrink manual text. No-space errors stay visible; a long caption may still require shortening or manual editing.

Verification used the previously recorded band photograph in portrait and widescreen crops, with real Qt pointer drags and actual PNG exports. Correcting the portrait's false drum/window boxes and reviewing the face and lantern placed the unchanged caption in a three-line header instead of the previous seven-line column. Its reviewed regions had zero text overlap at export resolution. Fully protecting the wide photograph's three faces, guitar and drums rejected the old long caption rather than covering a subject. A separate explicit test caption, “My solo has a copay.”, fit in a two-line header with the same protection. Both successful PNGs matched their previews exactly and retained the mandatory visible credit. These are recorded-model replays with human correction, not evidence of accurate automatic detection or better generated humor.
